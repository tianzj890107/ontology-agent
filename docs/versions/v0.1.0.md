# 硕磐智能建模 v0.1.0

## 基本信息

- 版本：`v0.1.0`
- 日期：`2026-08-28`
- 状态：已定版
- Git Tag：`v0.1.0`

## 版本概述

硕磐智能建模首个完整可用版本：提供任务式 Agent 建模工作台（47313）与独立建模服务（47314），覆盖数据库、文档和自然语言三种建模入口，支持业务对象、逻辑实体、业务属性、实体关系、业务规则、业务术语、指标和动作的识别、校验与输出，并提供建模结果预览与本体可视化。

## 核心能力

- 数据库建模、文档建模、自然语言建模；
- 业务对象、逻辑实体、业务属性、实体关系识别；
- 业务规则、业务术语、指标、动作识别；
- 文件、CSV、Excel 和本体结果预览；
- 关系聚类可视化（Sigma/ForceAtlas2）与语义环形可视化（ECharts）；
- 任务/run 历史、事件记录、执行恢复；
- input/work/output 工作区隔离；
- 建模结果语义校验、决策审计和规范化上传门禁。

## 用户可见变化

- 47313 与 47314 统一产品名称为“硕磐智能建模”，产品显示版本统一为 `v0.1.0`；47314“服务已连接”状态保留；
- 47313 品牌区域不再显示“Agent”Tag；
- 文件预览与本体可视化 Modal：普通窗口模式保留圆角，全屏模式占满 viewport（100vw × 100dvh）且取消所有倒角；
- 独立建模服务正式接受 `actions.csv` 产物（映射为 ACTION），前端默认全选产物创建 run 成功，未知产物仍返回 422；
- 47314 独立建模服务与 47313 任务工作台并行运行，任务与 run 数据隔离。

## 可靠性与数据安全

- CSV 上传门禁与完成门禁分离，逐文件 stage/code 与部分成功语义；
- 上传记录双哈希（原始文件与规范化上传 blob）与完成哈希一致性校验；
- 本地原文件不覆盖，MinIO 对象使用规范化表头与正式字段值；
- 输入/工作/输出工作区隔离，删除运行数据必须遵守 AGENTS.md 安全规则。

## 兼容性

- 历史关系表头兼容别名（如“源关联属性编码”→“源业务属性编码”）；
- 关系分类英文别名（COMPOSITION/EXTENSION/REFERENCE 等）规范化为正式中文值；
- 中文名称允许包含英文缩写与数字，仅要求至少一个中文字符；
- 知识规范、元模型、模板和 CSV 契约版本仍为 `v0.0.1`，与产品 UI 版本 `v0.1.0` 相互独立。

## 验证情况

- 全量 Python 测试通过（当前分支最新状态）；
- 前端 Node 测试通过；
- 前端 production build 成功；
- `git diff --check` 通过。

## 已知限制

- 语义校验问题作为非阻断 warnings 保留在校验报告中，不阻止用户确认完成；
- 模型传输/协议类错误记录本地 error 供排查，平台任务保持 RUNNING/BLOCKED 可直接重试；
- 成功任务完成后输入框仍可见但禁止发送的行为需产品进一步确认。

## 升级说明

- 从更早版本升级需重新构建前端产物并同步 `frontend/dist`；
- 上传记录含 `normalizationVersion`，规范化版本变化时旧上传记录按 fail-closed 处理，要求重新上传。

## 版本管理

- 主协作代码位于 `origin/20260727`；个人私有镜像位于 `personal/main`；两个远端保存同一个 commit（`HEAD == origin/20260727 == personal/main`）。
- `v0.1.0` 使用 annotated Git tag；tag 同时保存在 origin 和 personal；tag 指向包含最终版本元数据的冻结 commit。
- `v0.1.0` tag 不再移动。
- 后续修复和小调整归入 `v0.1.1`；明显的新能力集合才升级 `v0.2.0`。
- 详细规则见 [版本管理规范](./versioning-policy.md)。
- tag 不等于 GitHub Release；tag 不等于部署。
