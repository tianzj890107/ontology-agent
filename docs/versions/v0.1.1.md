## 版本概述

v0.1.1 聚焦历史会话/历史运行的切换体验：为 47313 任务工作台和 47314 独立建模服务建立有界的内存会话缓存，并在会话打开时后台预加载本体可视化数据，减少切换会话与打开可视化时的等待。

## 核心能力

- 会话/运行内存缓存：47313 按 namespaced key（mission identity + taskId，无 mission 时为 task:<id>）保存任务快照、合并事件、事件窗口与 cursor、文件列表和本体 graph；47314 按 runId 保存。预加载、点击可视化、LRU 保护与请求代次使用完全相同的 key，不再用裸 taskId 查询。
- 切换回来即时恢复：A → B → A 切换时，A 的事件、文件列表、事件窗口和任务快照在详情请求返回前立即恢复，后台再请求最新详情与事件增量并幂等合并；旧请求的迟到响应由请求 generation 拦截，不能覆盖当前会话。
- 本体数据随会话后台预加载：文件列表就绪后立即下载并解析本体 CSV、执行 `buildOntologyGraph`，结果按会话缓存。
- 点击可视化复用缓存：有有效缓存直接打开；有同签名在途 Promise 时复用；没有缓存时现场加载并写回缓存。
- graph 产物签名失效：基于产物路径和可用元数据（size/mtime/modifiedAt 等）生成稳定签名，产物集合或元数据变化后自动重新构图。
- 请求去重与竞态保护：同一会话同一签名只有一个在途 Promise；迟到的旧响应不会覆盖新会话或新签名条目。
- LRU 上限：47313 task 与 47314 run 各缓存最多 10 个会话，只淘汰非活动会话，当前会话受保护。
- 缓存仅当前页面生命周期有效：不使用 localStorage/sessionStorage/IndexedDB，刷新后自然清空并重新加载。

## 用户可见变化

- 重新打开最近访问过的会话时，历史消息与文件列表不再从头全量请求，首屏恢复更快。
- 打开历史会话后，"本体可视化"通常已后台就绪，点击后立即打开，不再出现由网络读取和 CSV 构图造成的长时间等待。
- 会话产物更新（上传、覆盖、重新生成）后，本体图按文件签名自动刷新。
- 普通模式圆角与全屏模式无圆角行为保持不变（沿用 v0.1.0 契约）。

## 兼容性

- 不修改知识规范、元模型、模板和 CSV 契约版本（仍为 `v0.0.1`）。
- 不改变后端 API 与数据格式；缓存与预加载全部在浏览器内存内完成。
- 旧客户端行为不受影响：缓存缺失、预加载失败时回退到原有现场加载流程。

## 验证情况

- 新增 `frontend/src/sessionCache.js` 纯模块与可独立测试的开场/恢复辅助函数：`taskCacheKey`（namespaced key 生成）、`sessionSnapshotFor`/`restoreTaskPlan`（缓存快照恢复）、`mergeLogWindow`（事件窗口合并，cursor 不倒退）、`commitSessionSnapshot`（写回缓存并保护活动 namespaced key 的 LRU 淘汰）、`createOpenGate`（请求 generation 判定）；`eventSync.js` 的 `mergeEvents` 负责缓存事件与新事件的幂等合并。
- 47313 的 `openTask`、`loadFiles`、`preloadTaskOntologyGraph`、`drawOntology` 与 `activeTaskCacheKeyRef` 全部统一使用同一个 namespaced key；graph 预加载与用户点击共享同一在途 Promise，命中后不再重新下载同一批 CSV。
- 将原 `ontologyPreviewRuntime.test.mjs` 中只检查源码函数名的字符串测试替换为真实行为测试（预加载/点击同 key、在途 Promise 共享、LRU 保护、A → B → A 立即恢复、迟到响应拦截），保留少量接线契约断言直接防回归“drawOntology 用裸 taskId”这一缺陷。
- 修复 `ontologyForceLayout.test.mjs` 对仓库根目录运行时 `output/` 的依赖：新增可提交的合成五层 CSV 夹具 `frontend/tests/fixtures/five-layer/`，路径经 `import.meta.url` 相对解析，与运行目录无关。
- 验证：全部前端 Node 测试 107/107 通过，Python 全量测试与 `git diff --check` 通过，production build 成功。

## 已知限制

- 缓存仅在单个页面生命周期内有效；刷新或重新进入页面后需要重新加载。
- 预加载失败不会阻止会话打开，错误记录在会话缓存中，点击可视化时可重试。
