- 重构建模门禁处理机制（门禁动作模型专项，基于 commit `457c43e`）：
  - 门禁发现统一分为四类处理动作，不再由原始 severity 单独决定行为：`STRUCTURAL_BLOCKER`（真正无法消费的产物损坏，进入 Agent repair）、`DETERMINISTIC_NORMALIZATION`（服务端确定性修复后继续）、`FORMAL_ELIGIBILITY`（自动降级为 CANDIDATE/UNKNOWN 并从正式输出排除）、`QUALITY_WARNING`（PASSED）。`open_claude/modeling_reliability.py` 新增 `issue_action()`/`is_structural_blocker()`，`validate_modeling_stages` 与 `finalize_semantic_model` 的阶段/最终状态只按 `is_structural_blocker` 判 FAILED。
  - 服务端确定性规范化 `normalize_modeling_state()`（在 stage 校验与 finalize 前统一执行，幂等）：未处理资产自动补 `processingDecision=UNKNOWN`；弱 COMPOSITION 降级 REFERENCE；无证据/CARDINALITY 缺失/M:N 的 CONFIRMED 关系自动降级 CANDIDATE（M:N 额外标记 `needsRelationEntity`，不猜拆分）；FK/JOIN 证据的 TRANSFORMATION 重分类为 REFERENCE；UNKNOWN→CONFIRMED 无新证据的升级自动拒绝；BO confidence 无法解析置 `UNKNOWN`、可规范化转标准百分比、最终决策按 R1-R5 重算；CONFIRMED BO 无唯一主逻辑实体自动降级 CANDIDATE（`eligibilityBlockers` 留痕，决策层以服务端降级为准）；跨实体/循环证据自动移除并重算状态；FK 无决策自动补 `UNRESOLVED`；完全重复 mapping 确定性去重（同 key 不同内容仍 ERROR）；指向非 CONFIRMED BO 的实体归属自动降 `UNRESOLVED`；确认技术字段自动从正式属性排除（保留逻辑主键属性，名称启发式不排除）。
  - 明确退出 Agent repair loop：`UNSUPPORTED_CONFIRMED_RELATION`、`TRANSFORMATION_EVIDENCE_GATE`、`UNSUPPORTED_STATUS_UPGRADE`、`V0001_FORMAL_*` 系列（主实体数量/逻辑键/基数/M:N/主标记归属）等为 FORMAL_ELIGIBILITY 非阻断；`CROSS_ENTITY_EVIDENCE`、`CIRCULAR_EVIDENCE`、`FK_COVERAGE_MISSING`、`INVALID_BUSINESS_OBJECT_CONFIDENCE`、`BUSINESS_OBJECT_DECISION_COUNT_MISMATCH`、`INVALID_BUSINESS_OBJECT_ASSIGNMENT`、`TECHNICAL_ATTRIBUTE_IN_FORMAL_OUTPUT` 为 DETERMINISTIC_NORMALIZATION 非阻断；`V0001_DESCRIPTION_MISSING`、`V0001_ATTRIBUTE_SPECIAL_CHARACTER` 改 WARNING（仅名称缺失、编码重复、CSV/schema 损坏、正式输出为空/缺必要列等真实结构错误继续 ERROR 阻断）。
  - 审计覆盖 `DECISION_AUDIT_COVERAGE`：缺失/过期审计文件在 finalize 时由服务端从 canonical `modeling_state.json` 确定性重建，重建后仍不可恢复才 ERROR；不再因“已有 marker + 缺文件”直接硬失败。
  - safety valve 与 gate retry 只对结构性阻断累计：`_modeling_gate_signature`/`observe_gate` 仅统计 `STRUCTURAL_BLOCKER`，证据不足、UNKNOWN/CANDIDATE、确定性修复与质量 WARNING 不消耗 `gate_retries`、不触发 `MODEL_GATE_REPEATED_WITHOUT_NEW_EVIDENCE`；`_gate_blocker_detail`、`block_modeling`、`finalize_modeling_task` 的 errors 只取结构性阻断。
  - 校验缓存：`_STAGE_STATE_KEYS` 纳入规范化产物（`assetDecisions`、`autoResolvedProcessingDecisions`、`businessObjectDecisionSummary`、`mappingDefinitions` 等），`VALIDATION_CACHE_VERSION` 升级为 `2026-08-19-gate-action-normalization-v2`，旧 FAILED 阶段缓存自动失效，确定性修复后的状态不会命中修复前缓存。
  - 新增 `tests/test_gate_action_normalization.py` 共 29 个回归测试，覆盖：动作分类、evidence 自动清理降级、confidence/决策重算、审计重建、FK/资产覆盖、关系/主实体/技术字段降级、描述与特殊字符 WARNING、malformed CSV 与重复编码仍 FAILED、非结构性问题不累计 gate retry、相同语义问题不触发 repeated safety valve、旧 FAILED 缓存不阻断规范化状态。更新 `test_semantic_finalize_upload_boundary.py`（无证据关系降级后 PASSED、审计重建、malformed 输出 FAILED）与 `test_v0001_rule_registry.py`（缺定义 WARNING、缺名称 ERROR）。

- 修复 47313/47314 共用的 DeepSeek provider 共享层故障（reasoning-only assistant 400 循环）：
  - 根因链：DeepSeek 流式响应在 reasoning 阶段静默 → openai SDK read timeout（600s）→ `_stream_once()` 把仅含 thinking 的半截 turn 持久化为 assistant 消息（无 content、无 tool_calls）→ 继续运行加载该非法历史 → DeepSeek 拒绝 `Invalid assistant message: content or tool_calls must be set` → 旧 `_is_recoverable_provider_error` 不识别、`sanitize_messages` 不清 reasoning-only → 每次继续重复 400。
  - 共享层 `open_claude/openai_compat.py`：新增显式 provider transport timeout（`ONTOLOGY_LLM_CONNECT_TIMEOUT/READ_TIMEOUT/WRITE_TIMEOUT/POOL_TIMEOUT`，默认 5/600/600/600，`provider_timeout_config()`/`_provider_timeout()` 生效于 `_client()`），启动日志打印非敏感 timeout 摘要；`_is_provider_timeout()` 识别 SDK 超时并返回独立 `LLM_STREAM_TIMEOUT`（`stream()` 产出 `{"type":"error","code":"LLM_STREAM_TIMEOUT","recoverable":True,"error":"模型流式响应长时间无数据，本轮已暂停，可继续执行"}`，不盲目重试）；`_assistant_has_sendable_payload()` + `sanitize_messages()` 幂等丢弃仅 thinking/空 content 的 assistant；`to_openai_messages()` 不再输出 `content=None` 的 reasoning-only assistant（保留后续 user 消息与完整 tool-call/tool-result 配对）；`_is_recoverable_provider_error()` 新增 `content or tool_calls must be set`/`invalid assistant message` 标记，仅重试当前 LLM 步骤。
